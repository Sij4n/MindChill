## Refresh the captures

1. Use the current app build and a separate browser profile or local origin so existing personal notes/tasks are not exposed or overwritten.
2. Start the app using [the documented setup](../DEVELOPMENT.md#setup-and-commands). Use a temporary local server when needed and stop only the server you started after capture.
3. Set a consistent desktop viewport of 1440 × 1000 and a mobile viewport of 390 × 844. Let the layout settle after resizing.
4. Dismiss the welcome screen. Enable Still scene and sage for these reference views. Mute audio while capturing if desired.
5. Use sample tasks such as “Read one chapter” and “Write a short summary.” Use illustrative notes rather than real personal content.
6. Capture the real workspace and each panel. Inspect the saved images for layout changes, readable text, clipping, focus artifacts, and private information.
7. Preserve filenames where the view is unchanged, update the capture date and table, and check all links from the README and guide.
8. Do not use `?promo=true` or older root-level preview files as replacements for current product screenshots.

Avoid accepting camera/microphone permissions just to create a screenshot. A study-room image should use an authorized test session and omit identifying room codes and real participant video unless they are intended for publication.
